# mcp-doctor v0.4.1

`v0.4.1` is a security patch for Unix STDIO interruption cleanup. Published
versions `0.1.0` through `0.4.0` can leave a managed target process tree
running when `mcp-doctor` itself receives `SIGINT` or `SIGTERM`. Users of Unix
STDIO diagnostics should upgrade to `0.4.1`.

## Interruption contract

For `inspect`, `check`, `break`, and `reject` over STDIO on Unix, `mcp-doctor`
now registers catchable interruption handling before artifact preparation,
input work, or target launch. After observing `SIGINT` or `SIGTERM`, it:

- sends no subsequent MCP request or notification, including an active
  workflow cleanup suffix or the optional second `inspect auto` lifecycle;
- closes target stdin and allows 2,000 ms for graceful whole-tree exit;
- forcibly terminates the managed process group and allows another 2,000 ms
  to reap it;
- removes its identity-owned report stages and publishes no stdout diagnostic,
  snapshot, or report artifact; and
- exits `3` (`incomplete_evidence`) after clean interruption.

The complete interruption cleanup ceiling is 4,000 ms from signal observation.
Cleanup, artifact rollback, stdout, or status failure instead exits `4`.
`--status jsonl` keeps `mcp-doctor.status/v1` and identifies the clean case with
the optional terminal field `completion_reason: "interrupted"`.

Interruption wins until cleanup and the final check before report publication.
Once report publication begins, the completed diagnostic wins. Repeated
catchable signals remain coalesced during bounded cleanup rather than forcing
an early exit. `SIGKILL` cannot be caught and remains outside this contract.
Streamable HTTP, offline commands, and Windows behavior are unchanged.

The stable capability document exposes the Unix STDIO signal set, affected
commands, the 2,000 ms graceful and forced-reap phases, combined 4,000 ms
ceiling, exit code, status reason, report policy, and repeated-signal behavior.
Built-binary regressions cover both catchable signals, a resistant descendant,
artifact rollback, status and registration failure, passive auto-selection,
and suppression of a later side-effecting workflow cleanup call.

## Dependency review

This patch adds no dependency and does not change the resolved package graph.
It narrowly enables Tokio's existing `signal` feature at exact version
`1.53.1`; the repository inventory records that selected feature. Signal
handling uses Tokio's maintained Unix integration, while existing
`process-wrap` process-group ownership remains responsible for whole-tree kill
and reap.

## Upgrade

```bash
cargo install mcp-doctor --version '=0.4.1' --locked
```

Homebrew and GitHub Release users should select `v0.4.1` after its immutable
release and channel verification complete.
