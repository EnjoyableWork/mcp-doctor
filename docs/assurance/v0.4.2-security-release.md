# v0.4.2 bounded hostname-resolution teardown security-release record

This non-sensitive record closes the hostname-resolution teardown advisory on
2026-09-03. It records only public commits, pull requests, workflow runs,
release artifacts, installation channels, and the published advisory. It
contains no private reproducer, endpoint, resolver payload, credential, local
path, or advisory-workspace material.

## Scope and outcome

Published `mcp-doctor` versions `0.2.0` through `0.4.1` could finish a typed
hostname-resolution timeout diagnosis yet keep the CLI process alive while the
operating-system resolver remained blocked. The system lookup runs through
Tokio's blocking pool and cannot be cancelled through its operating-system API;
unbounded runtime destruction therefore outlived the command's diagnostic
deadline.

`v0.4.2` owns one current-thread Tokio runtime explicitly and gives its
post-command shutdown at most 100 ms to wait for blocking work. The correction
does not cancel the resolver or change DNS, retry, redirect, connection, TLS,
credential, private-network, redaction, report, or exit semantics. The stable
capability document exposes `limits.runtime_shutdown_timeout_ms: 100` and
retains `whole_process_exit_guarantee: false` because synchronous preparation
and report publication remain outside diagnostic deadlines.

The patch adds no dependency, feature, build script, unsafe code, or resolved
package. A deterministic built-binary regression acknowledges entry into
synthetic non-cancellable resolver work, withholds its release, and proves the
typed `network.resolution` diagnosis and bounded process exit under one outer
watchdog.

existing cross-platform peer-close classifier while retaining the 20-second
