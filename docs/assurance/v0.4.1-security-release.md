# v0.4.1 Unix interruption security-release record

This non-sensitive record closes the Unix STDIO interruption advisory on
2026-09-03. It records only public commits, pull requests, workflow runs,
release artifacts, installation channels, and the published advisory. It
contains no private reproducer, process payload, target output, credential,
local path, or advisory-workspace material.

## Scope and outcome

Published `mcp-doctor` versions `0.1.0` through `0.4.0` could leave a managed
STDIO target process tree running when the CLI received `SIGINT` or `SIGTERM`
on Unix. A PID-directed signal could terminate `mcp-doctor` under the default
signal disposition while a target or resistant descendant in its separate
process group retained resources or continued already-authorized work.

`v0.4.1` registers catchable Unix interruption handling before target launch,
stops later protocol work, closes stdin, owns bounded graceful and forced
whole-tree cleanup, reaps the process group, rolls back identity-owned report
stages, and publishes no partial diagnostic artifact. A clean interruption
exits `3`; cleanup or publication failure exits `4`. Streamable HTTP, offline
commands, Windows Job Object cleanup, and `SIGKILL` are outside the corrected
cause and contract.

The patch adds no dependency and does not change the resolved package graph.
It enables Tokio's existing `signal` feature at exact version `1.53.1` and
retains the existing `process-wrap` process-group ownership boundary.

## Preserved public failures and correction

The first public candidate `3028d2d683bf13cab8e8ceb4e35060fb63430a83`
preserved two independently actionable integration failures. Its
[CI run](https://github.com/EnjoyableWork/mcp-doctor/actions/runs/33705162938)
and [release preflight](https://github.com/EnjoyableWork/mcp-doctor/actions/runs/33705162922)
failed on Windows because the non-Unix no-op used a `const async fn` shape
that stable Rust rejected. Its repository-owned
[`mcp-doctor` run](https://github.com/EnjoyableWork/mcp-doctor/actions/runs/33705162929)
correctly rejected an attempted `0.4.1` download because no immutable release
existed yet. The first candidate's
[CodeQL run](https://github.com/EnjoyableWork/mcp-doctor/actions/runs/33705161875)
passed, as did the unaffected native jobs.

Commit `5ea157c74da0ed13c71a0cd2f5451b1a50bed4a6` made the non-Unix function a
regular `async fn` and restored all published-artifact workflow pins to
`0.4.0` until release. No unchanged-source job or workflow was rerun. The
corrected head then passed first-attempt
[CI](https://github.com/EnjoyableWork/mcp-doctor/actions/runs/33705872376),
[release preflight](https://github.com/EnjoyableWork/mcp-doctor/actions/runs/33705872402),
[CodeQL](https://github.com/EnjoyableWork/mcp-doctor/actions/runs/33705869770),
and the pinned
[`mcp-doctor` check](https://github.com/EnjoyableWork/mcp-doctor/actions/runs/33705872268).
