# `mcp-doctor` v0.4.0 standalone category evaluation

**Evaluated release:** `v0.4.0`

**Evidence cutoff:** 2026-08-20T17:09:22Z

**Row lock:** 2026-08-20T17:28:57Z

**Rubric:** [Category audit rubric v1](category-audit-v1.md)

**Result:** **80/100**, standalone and dated

This page publishes a historical evaluation of one immutable `mcp-doctor`
release against a project-defined rubric. It is not MCP conformance,
certification, security assurance, external endorsement, a comparison, or a
ranking. No competitor identity was in scope.

The row classifications were made by one language-model evaluator. They were
not repeated or calibrated across model versions or providers, so this result
is not a model-portable benchmark. The artifact observations, row lock, fixed
state-to-point mapping, and arithmetic have stronger deterministic evidence
than the evaluator's classification judgments.

## Method and independence

Rubric v1 contains 25 rows in five weighted categories. Protocol and
agent-facing rows use `Full = 5`, `Partial = 3`, `Zero = 0`; security and
developer-experience rows use `4`, `2`, `0`; trust rows use `2`, `1`, `0`.
Each row's specific conditions and evidence minimum are public in the
[rubric](category-audit-v1.md).

Before evaluation, the rubric, release identity, empty comparison set,
environment, evidence cutoff, and allowed sources were frozen. The evaluator
declared before evidence access that it had not seen a prior numerical result,
proposed state, predicted delta, target outcome, desired rank, competitor
result, scored worksheet, or comparison identity. It then recorded a state,
evidence, rationale, and limitations for all 25 rows before points were shown
or calculated.

## Released-artifact reproduction

The primary artifact observations used macOS 26.5.2 build 25F84 on ARM64 with
`rustc 1.97.1` and `cargo 1.97.1`. The installed `mcp-doctor` binary was
14,203,392 bytes; the exact-release fixture binary was 1,152,272 bytes.
Public workflows listed below provide the represented Linux and Windows

The following uses only an exact public package, an exact source commit, and a
repository-owned synthetic STDIO fixture. It calls no MCP tool and uses no
credential, private endpoint, or production target.

```bash
audit_root="$(mktemp -d)"

cargo install mcp-doctor \
  --version '=0.4.0' \
  --locked \
  --root "$audit_root/tool"

git clone https://github.com/EnjoyableWork/mcp-doctor.git \
  "$audit_root/source"
git -C "$audit_root/source" checkout --detach \
  074a62dbbfce5fa417f2b7080d509ebd86433b1f
cargo build \
  --manifest-path "$audit_root/source/Cargo.toml" \
  --release \
  --locked \
  --features internal-test-fixtures \
  --bin mcp-doctor-stdio-fixture

fixture_mode=catalog-valid
mkdir -p "$audit_root/reports"
"$audit_root/tool/bin/mcp-doctor" inspect \
  --protocol-version 2026-07-28 \
  --json-report "$audit_root/reports/report.json" \
  --junit-report "$audit_root/reports/report.junit.xml" \
  --markdown-report "$audit_root/reports/report.md" \
  --badge-report "$audit_root/reports/badge.json" \
  -- "$audit_root/source/target/release/mcp-doctor-stdio-fixture" \
  "$fixture_mode"
```

## Checks not performed and interpretation limits

- The evaluation used synthetic fixtures only. It did not call a real tool,
  production server, private endpoint, or credentialed target.
- Comparison identities were frozen as empty. Historical scores were not
  revealed to the evaluator, and no comparison, rank, or leadership result is
  valid.
- The E1 environment was macOS ARM64. Public exact-artifact workflow evidence
  covers represented Linux and Windows boundaries.
- Representative released-artifact cases were observed directly; some complete
  clause coverage is exact-release automated evidence, as identified per row.
- P2 lacks a matching released-artifact Streamable HTTP observation. A1 lacks
  reused-description detection. A2 is root-only. A3 has no qualifying context
  metrics. S5 covers one of three diagnostic classes. D4 was incomplete at the
  release-source boundary. D5 has no qualifying profile. T4's compact badge
  omits required evaluation context.
- The compatibility matrix is finite passive STDIO evidence. It does not prove
  HTTP reach, every MCP server, every protocol behavior, or universal
  conformance.
- Evaluator repeatability and cross-model agreement were not measured. The
  standalone total must not be described as provider-neutral or model-portable.

limitations. Under rubric v1, presenting it as a current result expires after
